🏗️ Clean Architecture

Controller → Application → Domain → Repository pattern with clear separation of concerns and dependency inversion

🔄 Idempotency

ExternalRef uniqueness guarantees, result replay for duplicate requests, 24-hour key retention

📊 Double-Entry Ledger

Atomic debit/credit pairs, stored procedures for consistency, balance recomputation, immutable entries

📤 Outbox Pattern

Reliable event delivery, at-least-once guarantee, background polling, consumer idempotency

⚡ Performance

Redis caching for hot data, distributed locks for concurrency, connection pooling, query optimization

🔍 Observability

Structured logging, distributed tracing with correlation IDs, Prometheus metrics, real-time alerts

💡 Transaction Processing Flow

  1. Request arrives → Gateway validates JWT/HMAC, checks rate limits, verifies idempotency key
  2. Service layer → Validates business rules, checks limits, verifies wallet status and balance
  3. Domain layer → Applies business logic, generates domain events, creates transaction entity
  4. Ledger posts → Stored procedure creates double-entry (debit/credit), updates balances atomically
  5. Outbox write → Domain events written to outbox table in same SQL transaction
  6. Commit → Single database transaction commits, ensuring consistency
  7. Event dispatch → Background worker polls outbox, publishes to message queue
  8. Notifications → Consumers send SMS/push notifications, trigger settlements
